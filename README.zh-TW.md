# 微塑膠 AI 監測系統

> **以合成資料建立的研究原型。** 影像、光譜和監測站都是模擬的。光譜特徵只是示意，不是實測的聚合物光譜。結果呈現的是這套流程的行為，不是經過現場驗證的準確度。

本專案依據第 16 章「智慧環境監測：整合 AI 系統進行全面的微塑膠監測與分析」實作，包含兩種量測方式：

| 方式 | 流程 | 適合 |
|---|---|---|
| **A. 濾膜取樣**（書中方法） | 每週採 10 L 水 → 過濾 → 拍攝濾膜 → AI 計數 | 低濃度的河川、湖泊；需要人工採樣 |
| **B. 透明管線上探頭（新增）** | 水連續流過透明管 → 頻閃相機拍攝流動中的微粒 → 追蹤計數 → MQTT 上傳 | 連續、自動監測，例如污水廠進出流；低濃度時需要前置濃縮 |

## A. 濾膜取樣（書中圖 16.1 的四個元件）

| 元件 | 模組 | 實作內容 |
|---|---|---|
| 電腦視覺（16.3.2） | `vision.py` | 粗網格中位數去背景（處理混濁）、MAD 自適應門檻（處理曝光變化）、連通區域，以及 13 個特徵：大小、長寬、長寬比、圓度、實心度、亮度、紋理、4 個正規化光譜波段 |
| 機器學習（16.3.1） | `ml.py` | 兩個隨機森林：材質（PE/PP/PS/PET/有機物/礦物/非微粒）與形狀（珠粒/碎片/纖維/薄膜）；只用 5 % 標註的自我訓練；黏在一起的微粒造成少算，用計數校正補回 |
| 即時偵測（16.3.3） | `network.py` | 每個樣本在邊緣端分析（單核約 0.5 秒）、超過行動值時警示、存入 SQLite |
| 資料處理與分析（16.3.4、16.4.4） | `network.py`、`report.py` | 每月標準品品管（回收率 80–120 %）、品管失敗後的資料加註、Mann–Kendall 趨勢、熱點、簡易預測 |

### 結果（`docs/results.md`）

| 書中說法 | 本原型結果 |
|---|---|
| 「準確率可達 95 %」 | **已分割出的微粒，分類成立**：材質 97–99 %，聚合物辨識 98–99 %。**密集濾膜上的計數不成立**：只有約 80 % 的微粒被單獨分割，因為相碰或重疊的微粒會黏成一塊。稀疏濾膜上是 91 %。 |
| 誤報 < 3 % | 依水質為 0.8–3.4 %（天然顆粒被誤判成塑膠） |
| 風化微粒「略低」 | 若訓練資料沒有風化微粒，遠不只「略低」：找到的微粒從 80 % 掉到 **15 %**。訓練加入風化樣本後恢復到 80 %。 |
| 混濁水中偵測 > 90 % | 分類成立（精確率 99.7 %）。偵測受分割限制（83 %），50 µm 以下的微粒在混濁水中受影響最大。 |
| 每月標準品品管 | 必要但太慢。球形珠粒標準品在相機漂移開始 10 週後才判定失敗。漂移的監測站在品管發現前，有 6–10 週回報了錯誤的「下降」趨勢。標準品加入纖維，可提早 2 週發現。建議另外對每張影像做清晰度自我檢查。 |
| 多光譜／高光譜辨識 | 在本模型中確認是必要的：只用灰階相機加形態特徵，材質準確率降到 59–67 %，聚合物辨識只剩 43–52 %。 |
| 半監督學習 | 只標註 5 % 的自我訓練，材質準確率可達 95–97 %，接近全標註。 |

* **計數校正**：用單一比例（真實 ≈ 1.21 × 預測）校正後，每張影像的計數誤差從 15–22 % 降到 6–12 %。
* **趨勢檢定也有陷阱**：
  * 海灘站顯示顯著的「下降」，其實只是季節週期的一半。
  * 湖泊站出現 p = 0.043 的「上升」，在 α = 0.05 下屬於偽陽性。
* **§16.4 的三個系統名稱查不到出處**：POSEIDON-ML、AutoPlastic Detector、SmartScan-MP 引用的是文獻 [15]–[17]，但這些文獻是關於動物健康、痰液中的微塑膠和 FLIM 影像，沒有一篇描述這些系統，所以它們的效能數字無法查證。

## B. 透明管＋感測探針 IoT 線上量測模組（`flow.py`、`probe.py`）

```
 河水／污水 ─► 前置過濾 1 mm ─► 除氣泡器 ─► 蠕動幫浦 ─► 流量計 ─► 透明流通槽 ─► 排放
  （可選：前置濃縮 1000×）                              │
                                     LED 頻閃 ─────────┤────── 全域快門相機 + 遠心鏡頭
                                     矽膠刮片（伺服馬達） │
                                                   樹莓派 5：分割 → 分類 → 追蹤 → 計數
                                                        │ MQTT
                                     mpmon/<站>/probe/telemetry · alarm · cmd
```

微粒在流動中被拍攝，產生濾膜方法沒有的問題。本模組逐一模擬：

| 問題 | 模擬內容 | 對策 |
|---|---|---|
| 層流速度分布 | 圓管中心速度是平均的 2 倍，靠管壁幾乎不動；纖維順著流向 | 追蹤時每條軌跡有自己的速度 |
| 景深 | 物鏡只在約 0.3 mm 厚的範圍內清晰 | 改用**扁平流通槽**（深 0.3 mm） |
| 動態模糊 | 連續照明會讓移動中的微粒變成拉長的條紋 | **LED 頻閃 20 µs** |
| 漏拍與重複計數 | 慢的微粒出現在多張畫面，快的可能在兩張畫面之間通過 | **逐格追蹤**，每顆只算一次；流量不超過「視野體積 × 幀率」 |
| 氣泡 | 圓形、明亮，是典型的誤報來源 | 分類器加入「氣泡」類別，上游加除氣泡器 |
| 觀察窗髒污 | 生物膜讓影像變暗，微粒（包括塑膠）黏在管壁上 | 不動的物體由追蹤濾除；透光率低於 0.7 時自動刮窗 |
| 實際取樣體積 | 濃度 = 計數 ÷ 實際看到的水量 | 加入已知濃度的標準珠粒，量測回收率並校正 |

### 結果（`docs/flow-results.md`、`docs/flow.png`、`docs/flow-demo.png`）

1. **不要用圓管，要用平面壁的流通槽。**
   * 1 mm 圓管中只有 49 % 的水在景深內：20–50 µm 的微粒只找到 59 %。標準珠粒回收率會隨大小改變（93–226 %），所以無法可靠校正。
   * 1 × 0.3 mm 扁平流通槽：各尺寸都找到 100 %，計數與真實值的比 1.02，回收率 95–110 %。
   * 圓管的曲面還會像透鏡一樣扭曲影像（這點本模擬未計入），也是改用扁平槽的理由。
2. **追蹤是必要的。** 不追蹤、把每張畫面的偵測直接加總，扁平槽會多算 2.8 倍，圓管多算 6.5 倍，低流量時多算 6 倍。追蹤後的誤差在 ±5 % 以內。
3. **流量有上限。**
   * 20 fps 時，影像每張都換新一批水的上限約 0.74 mL/min，超過後會漏拍：1 mL/min 只找到 62 %，2 mL/min 只找到 30 %。
   * 改用 60 fps，1 mL/min 可恢復到 95 %。
   * 頻閃不可少：連續照明 5 ms 時，0.5 mL/min 只找到 23 %。
4. **氣泡**：分類器若沒有學過氣泡，塑膠計數會多出 1 倍（1.97 倍）。加入氣泡類別後為 1.00 倍。
5. **髒污**：72 小時不刮窗時，透光率降到 0.41，有 43 個物體黏在窗上。若不濾除不動的物體，計數會多 39 %；濾除後仍準確（0.95），但找到率從 94 % 降到 86 %。以背景亮度估算的透光率與真實值相差 ≤ 0.01，可直接用來觸發刮片。
6. **標準珠粒校正**（扁平槽，每次約 80 顆）：校正後濃度 1,605 /mL，真實 1,524 /mL。珠粒太少時，光是統計誤差就有 ±20 % 以上。第一次試跑時每次只有 31 顆，校正結果反而變差。
7. **最重要的限制：計數時間。** 最佳操作點約 0.5 mL/min，每小時只看得到約 28 mL 的水。要達到 ±20 % 的精度，大約需要 96 顆微粒：

   | 河水濃度（顆/L） | 直接量測 | 前置濃縮 1000× |
   |---:|---:|---:|
   | 1 | 142 天 | 3.4 小時 |
   | 10 | 14 天 | 20 分鐘 |
   | 100 | 34 小時 | 2 分鐘 |
   | 1,000 | 3.4 小時 | < 1 分鐘 |

   **結論**：線上探頭適合污水廠或工業排放這類高濃度水，或前面加上濃縮裝置（例如篩網濃縮、水力旋流器）。一般河川和湖泊仍以濾膜取樣為主，線上探頭可作為異常事件的即時警報。
8. **IoT 節點示範**（12 個量測窗）：
   * 汙染事件（濃度 4 倍）在兩個量測窗都觸發 `concentration_high`，且只在 95 % 信賴區間下限超過行動值時才警示，避免誤報。
   * 氣泡事件觸發 `bubbles_check_degasser`。
   * 透光率 < 0.7 時，節點在本地自動刮窗，共 3 次，不需等待雲端。
   * 幫浦故障觸發 `flow_low`，該窗不做分析。
   * 雲端可下達指令：`{"cmd":"wipe"}`、`{"cmd":"set_flow","ml_min":0.5}`、`{"cmd":"calibrate","recovery":0.97}`。

### 建議硬體（未在實機上測試）

| 元件 | 建議 | 說明 |
|---|---|---|
| 流通槽 | 方形或扁平的硼矽玻璃／石英毛細管，內徑 1 × 0.3 mm（或 1 × 1 mm 方管） | 平面壁沒有透鏡效應；深度不超過景深 |
| 相機 | Raspberry Pi Global Shutter Camera（IMX296，60 fps） | **必須是全域快門**，捲簾快門會讓移動的微粒變形 |
| 鏡頭 | 2–4× 遠心鏡頭（約 4 µm/像素） | 放大倍率不隨深度改變，尺寸量測才準 |
| 照明 | 高功率 LED + MOSFET 驅動，由相機觸發，脈衝 10–20 µs | 不需要時也可做多波長或 Nile Red 螢光 |
| 流量計 | Sensirion SLF3S-1300F（I²C） | `probe.FlowSensorSLF3S` |
| 幫浦 | 蠕動幫浦（0.1–2 mL/min） | 由節點的 `set_flow` 指令控制 |
| 除氣泡與過濾 | 氣泡收集器 + 1 mm 前置網 | 避免氣泡誤報與堵管 |
| 刮片 | 微型伺服馬達 + 矽膠刮片，或超音波清洗 | `probe.WiperServo` |
| 運算 | 樹莓派 5 | 本機 PC 上每張畫面約 90 ms（含模擬繪圖）；樹莓派上的速度尚未實測 |

**多光譜的注意事項**：本模擬假設 4 個波段同時取得。如果改成用不同波長的 LED 輪流拍攝，微粒在兩張畫面之間已經移動，波段會對不上。實機需要多感測器的分光相機，或改用單一螢光通道。

## 安裝與使用

```bash
cd D:\robot\microplastic-ai-monitor
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\python -m pytest                  # 18 項測試（約 1.5 分鐘）
.venv\Scripts\python -m mpmon demo              # docs/demo.png：單一濾膜視野的標註結果
.venv\Scripts\python -m mpmon report            # 濾膜方法與監測網（約 3 分鐘）
.venv\Scripts\python -m mpmon flow              # 透明管線上探頭與 IoT 節點（約 8 分鐘；--quick 約 4 分鐘）
```

## 下一步

1. 用真實影像取代 `render.py`，例如 Nile Red 螢光、濾膜的 FTIR／拉曼影像，或流通槽的實拍影片。
2. 加入分水嶺或實例分割，把相碰的微粒分開。這是濾膜方法最大的誤差來源。
3. 線上探頭的實機驗證：用已知濃度的標準珠粒做流量掃描，確認上表的漏拍上限與回收率。
4. 行動值 50 顆/L 只是示範。水中微塑膠目前沒有法規限值，需依現場另訂。
